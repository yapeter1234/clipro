# ADR-001: Media intake and storage

- Status: Accepted for M1 prototype
- Date: 2026-11-19

## Decision

Next.js is the browser studio. Uppy 6 with its AWS S3 plugin manages browser-side multipart requests using one custom signRequest callback. Cloudflare R2 stores source media, proxies, thumbnails, timelines and renders in a private bucket. Supabase Auth + Postgres provides identity, workspace membership and asset/job records. FastAPI owns source validation, multipart orchestration and asset state. Modal runs short-lived media workers. FFmpeg/ffprobe is the deterministic media foundation.

## Upload sequence

1. Browser submits source metadata and file metadata to FastAPI.
2. FastAPI verifies Supabase JWT, workspace membership, source method, rights, file type and configured size.
3. FastAPI creates the R2 multipart upload and persists the Clipro asset/session in Postgres.
4. Browser attaches the returned R2 upload ID/key to Uppy file resumable state.
5. Uppy asks FastAPI to sign each multipart S3 operation (ListParts, UploadPart, CompleteMultipartUpload, AbortMultipartUpload).
6. Browser transfers parts directly to private R2.
7. Browser asks FastAPI to finalize; FastAPI verifies the completed object's size and asset metadata.
8. A Modal worker probes the media, computes checksum and creates a proxy/thumbnail.

## Security

- Supabase JWTs are verified against the project's asymmetric JWKS endpoint. Legacy HS256 verification is not enabled.
- Upload actions require workspace membership with owner/admin/editor role and uploader identity.
- R2 keys are generated by the server; client-proposed paths are never used.
- Only short-lived presigned multipart URLs reach the browser. R2 credentials never leave the API.
- Keep the bucket private and scope the R2 API token to that bucket.
- Browser MIME/extension checks are preliminary; ffprobe checks actual media after upload.
- Filenames and source URLs are untrusted metadata. The API never fetches arbitrary public video URLs.
- Multipart completion is performed by Uppy directly against R2, then verified by the API before state changes to uploaded.
- API CORS allows only CLIPRO_WEB_ORIGINS. R2 CORS must allow the app origin and expose ETag.
- Configure an R2 lifecycle rule to abort incomplete multipart uploads after the upload-session TTL.
- No social publishing credentials or automatic publishing endpoint exist.

## Setup dependencies

Apply supabase/migrations/202611190001_m1_media_uploads.sql, create the private R2 bucket, configure R2 CORS and set variables from services/api/.env.example as secure environment variables or Modal Secrets. Do not commit secrets. Do not deploy publicly until auth, database and R2 settings are configured.

The browser intake UI is in apps/web. Media probing, AI analysis and rendering are separate worker milestones and are not yet connected.
